# Commit identity and attribution policy

For maintainer-directed AI-assisted implementation, use Git author `Mojtaba Arvin <m.arvin@live.com>` only after confirming this exact email is associated with the maintainer's GitHub account. Do not use model, assistant, AI-agent, Copilot, Claude, Cursor, Codex, Gemini, generic agent, or bot identities as the author. Do not add bot/AI `Co-authored-by` trailers.

Include `<!-- maintainer-directed-ai-work -->` in the PR body for owner-authorized AI-assisted work. This machine-readable marker requires at least one commit whose GitHub author account is `mojtaba-arvin`; every commit attributed to that account must use the exact maintainer name/email. Other human contributor identities remain unchanged. Disclose AI assistance in the PR description; the marker does not claim the maintainer personally typed every line.

Preserve every real human contributor's original author name/email. Never relabel another person as the maintainer and never rewrite historical commits. Agent changes must be separate maintainer-authored commits.

Genuine GitHub Actions/Dependabot automation may author a commit only when it was actually generated by that automation and the PR has the explicit `allow-automation-commits` label. The validator additionally requires the GitHub author account to be one of the two exact allowlisted bot accounts. This label is an owner authorization, not cryptographic proof of automation provenance. It does not cover agent-written implementation. Bot co-author trailers remain prohibited. A `web-flow` committer is distinct from the commit author and must not be mistaken for an author identity.

Convenience defaults (not enforcement):

```sh
git config --global user.name "Mojtaba Arvin"
git config --global user.email "m.arvin@live.com"
```

`scripts/check_commit_identity.py` checks all paginated PR commits, rejects missing author metadata, known bot/agent authors and bot/AI co-author trailers, preserves other human authors, and enforces the maintainer identity when the marker is present. It allows only the exact GitHub Actions/Dependabot author accounts with the explicit label. Its fixture tests cover human and mixed-human attribution, wrong/missing maintainer metadata, known bot and agent authors, human/bot co-author trailers, and both approved automation accounts.

The `Commit identity` workflow uses the `pull_request` event with explicit read-only `contents` and `pull-requests` permissions, no secrets beyond the read-only `GITHUB_TOKEN`, and no credential persistence. It checks out the PR merge commit. Do not change it to `pull_request_target` or run PR-controlled code with elevated permissions.

A workflow is not automatically a required merge gate. The active `Protect main` ruleset currently requires only `Android CI / Required checks`; it does not require `Commit identity`. Configure the latter as a required status check through the repository's separately authorized ruleset process before treating this policy as a hard merge gate. The available GitHub integration cannot read branch protection and does not expose ruleset mutation; no protection was changed for this PR.

Git metadata is self-asserted: validation cannot prove who physically typed code or detect every disguised agent identity. The GitHub author account/email association provides attribution evidence, not proof of authorship. Confirm the email association and disclose AI assistance transparently.

Never amend, rebase, or cherry-pick a contributor's work under the maintainer identity. Preserve the contributor's original author fields and add a separate maintainer-authored commit for AI-assisted changes.
